# Research: Hotel and Transport Comparison

Facts below come from official documentation read during planning; **UNVERIFIED** marks anything to confirm against the live service when implementing.

## R1. LiteAPI sandbox (hotel provider)
- **Hosts**: data/search `https://api.liteapi.travel/v3.0`; booking `https://book.liteapi.travel/v3.0`. Header `X-API-Key`. The sandbox key is free; sandbox responses carry `sandbox: true`. Which host serves `/hotels/rates` is **UNVERIFIED** (docs show the api host).
- **Search**: `GET /data/hotels` with `countryCode` + `cityName` (or `latitude`, `longitude`, `radius` ≥ 1000 m), `limit`, `offset` → `data[]` with `id, name, city, country, latitude, longitude, main_photo, thumbnail, stars, rating, reviewCount, facilityIds`.
- **Details**: `GET /data/hotel?hotelId=` → `hotelImages[] (url, urlHd, caption, defaultImage)`, `hotelDescription`, `hotelFacilities`/`facilities[{facilityId,name}]`, `location.latitude/longitude`, `rooms[]`.
- **Reviews**: `GET /data/reviews?hotelId=&limit=&offset=` → `data[] (reviewId, averageScore, name, country, type, headline, pros, cons, date)`, `total`.
- **Live rates**: `POST /hotels/rates` body `{ hotelIds, checkin, checkout, currency, guestNationality, occupancies:[{adults, children:[ages]}] }` → `data[].roomTypes[].offerId` and `rates[].retailRate.total[].amount`. One entry in `hotelIds` gives the per-hotel room list; many ids give the list prices (or use `POST /hotels/min-rates` for cheapest-price listing).
- **Updated 2026-10-13**: `searchHotels` also takes the lodging type (the trip's accommodation preference) and either a city name or a point and radius (`near`); `listCountries` and `listCities` feed the dropdowns. Rates take a `rooms` count, the party shared between rooms with at least one adult in each.
- **Decision**: list view = `data/hotels` (content) joined with `hotels/min-rates` (price) for the page of hotel ids; details view = `data/hotel` + `data/reviews` + `hotels/rates` for one hotel. Rates are never cached and are re-checked at booking (plan 007).
- **Cache**: content and reviews cached 24 h in `http_cache`; search lists 10 min.
- **MCP**: an official hosted MCP exists (`https://mcp.liteapi.travel/api/mcp?apiKey=…`) but exact tool names are **UNVERIFIED** and the API key goes in the URL. **Decision**: use the REST API; the interface would hide a later switch.
- **Guest nationality**: required by the rates call; default from the account's country if known, else a configurable default (`GUEST_NATIONALITY`, default `US`).

## R2. Transitous (MOTIS) (transport provider)
- **Base**: `https://api.transitous.org/api/`. Endpoints from the MOTIS OpenAPI: `GET /api/v1/geocode?text=` (stops/places), `GET /api/v6/plan?fromPlace=&toPlace=&time=&arriveBy=&transitModes=` (itineraries). Plan/trip are `v6`, geocode `v1`; whether the public server currently serves `v6` is **UNVERIFIED**; the implementation reads the version from one constant and the quickstart checks it.
- **Response**: `itineraries[]` with `duration, startTime, endTime, transfers, legs[]`; legs carry `mode, from, to, agencyName, routeShortName, headsign`. Modes include `RAIL, HIGHSPEED_RAIL, LONG_DISTANCE, NIGHT_RAIL, REGIONAL_RAIL, BUS, COACH, FERRY, AIRPLANE, SUBWAY, TRAM`.
- **Fares**: schema has fare products but coverage is mostly empty (**UNVERIFIED** per feed). **Decision**: a real fare product, when returned, is used and labelled `confirmed`; otherwise the price comes from the fare estimator (R8) and is `estimated`.
- **Flights**: the Duffel test environment provides sandbox offers (Confirmed, marked sandbox) and test-mode booking; where it has none, no free real source exists. Flight rows show an indicative **price** from the fare estimator (`estimated`) and an indicative **duration** (`estimated`), while departure and arrival **times** stay `unavailable` (inventing a schedule would breach constitution III). A flight row is emitted when the traveler asked for flights (updated 2026-10-13: the "route long enough" trigger is not implemented; Flights is a default mode with Trains and Buses).
- **Policy**: non-commercial, open-source, light load; User-Agent with app name, version and contact on every call; link to `https://transitous.org/sources/` visible near results; no numeric rate limit stated, so calls are serialised and cached 10 minutes. Coverage for long-distance bus and ferry is likely patchy (**UNVERIFIED**).
- **Origin**: the traveler's origin is not collected by the specs; the provider needs one. **Decision**: the Transport filter row includes an "From" text field (geocoded with Transitous `geocode`); this is a UI addition inside the filter row required by the data source and is flagged as an open item. **Superseded 2026-10-13**: the free-text field was replaced by **Start country** and **Start city** dropdowns (lists from the hotel provider's countries and cities), saved on the trip; the API still geocodes the combined text with Transitous `geocode`. The destination is fixed by the trip.

## R3. OSRM (road travel times)
- `https://router.project-osrm.org/route/v1/driving/{lon},{lat};{lon},{lat}?overview=false` returns duration in seconds. Policy: non-commercial, ≤ 1 request/second, no uptime guarantee; driving profile only is assumed. Used for road legs (transfers to the hotel, itinerary travel time in plan 006). Results cached 24 h.

## R4. Nominatim (geocoding)
- `GET https://nominatim.openstreetmap.org/search?q=…&format=jsonv2&limit=1&countrycodes=…`; always set `format`. `lat`/`lon` are strings. Max 1 request/s for the whole application, identifying `User-Agent` (from `DATA_USER_AGENT`), cache results, no autocomplete. The in-process queue spaces calls ≥ 1.1 s; results go to `geocode_cache` keyed by normalised query. ODbL: "© OpenStreetMap contributors".
- Used for: destination coordinates when Open-Meteo geocoding lacks them, hotel addresses missing coordinates, itinerary stops.

## R5. OSM tiles and Leaflet
- Tile URL `https://tile.openstreetmap.org/{z}/{x}/{y}.png`; visible attribution "© OpenStreetMap contributors"; do not strip the Referer (no `Referrer-Policy: no-referrer`); no prefetch; tile URL configurable. `react-leaflet@4.2.1` (peer React 18, Leaflet ^1.9). Under Vite the default marker icon breaks: import the three marker PNGs from `leaflet/dist/images/` and call `L.Icon.Default.mergeOptions({...})` once; give the map container an explicit height.
- Static pin only; no live route or directions.

## R6. Sorting and filtering
- Hotels: sort by price (string-decimal compare), rating, location (distance from city centre, computed from coordinates), AI recommendation (score below). Transport: sort by price (unavailable last), duration, departure, AI recommendation; transport has no rating/location sort.
- **AI recommendation score**: deterministic blend (price vs budget share, rating, distance, availability, transport convenience) with weights in one constants file; a one-line reason per row ("Within your budget share; rated 4.6"). It is explained, not model-generated.
- Filter and sort state is kept in URL query parameters so tab switches and reloads keep it.

## R7. Selections
- One selected hotel (with chosen room snapshot) and one selected transport per trip, stored as rows. Selecting another replaces after a confirmation notice. The snapshot stores the price shown, certainty and `fetched_at`; booking re-checks live.

## R8. Indicative fare estimator
- **What it is**: a pure function `estimateFare({ mode, distanceKm, durationMinutes, currency, date })` in `api/src/transport/fareEstimate.ts`. It is **not** a provider and not mock data: it derives a price from real inputs (great-circle distance between the geocoded origin and destination, and the real timetable duration when Transitous supplied one) using published-style rule-of-thumb rates held in one constants file.
- **Rates (illustrative starting values, USD, editable in one place)**: train 0.12-0.22 per km; coach/bus 0.05-0.10 per km; ferry 0.20-0.40 per km plus a fixed port fee; flight short-haul (< 1,500 km) 45 + 0.09 per km, medium (1,500-4,000 km) 70 + 0.07 per km, long-haul (> 4,000 km) 140 + 0.06 per km; road (car) cost 0.12 per km (fuel and wear). The range's midpoint is shown as the price, the low and high are returned as `range`.
- **Currency**: the constants are USD; conversion to the trip currency uses the stored Frankfurter rate (plan 006), also `estimated`. No stored rate means the price is `unavailable`.
- **Duration for flights**: `distanceKm / 800 * 60 + 60` minutes (cruise speed plus ground allowance), `estimated`.
- **Labelling**: `certainty: 'estimated'`, `source: 'faro-estimate'`, `source_url: null`, `note: 'Indicative price from a distance-based model, not a quote'`, plus the assumptions (rate band, distance used). The UI shows the Estimated badge and a tooltip with the basis; the PDF and budget carry the same label.
- **Never**: the estimator never returns `confirmed`, never produces departure/arrival times, never runs when the distance is unknown (then the price is `unavailable`).
- **Open item**: the rate bands are generic and will not match real market fares; they are a placeholder for a real fare source (an additional provider could replace them without changing routes or UI).

## Implementation notes (verified against the live services, October 2026)

- **Transitous**: geocode is `v1`, plan is `v6`; both answer on the public server. Responses carry real itineraries with legs, agencies, line names and per-stop time zones. **Timetables cover only the next few weeks**: a Paris to Amsterdam search for 20 Oct 2026 returned 44 itineraries, the same search for 1 Dec 2026 and later returned none. For dates beyond the feeds the Transport tab says so and shows distance-based estimates (price and duration, labelled Estimated, no departure or arrival times) for trains and buses.
- **No fares**: the plan response contained no fare products, so every price is the Faro estimate (`api/src/transport/fareEstimate.ts`), badged Estimated with its basis and range. Exchange rates come from Frankfurter (ECB), cached 24 h.
- **Times**: MOTIS returns UTC; each row carries the origin and destination time zones and the UI shows local clock times.
- **Modes**: train, bus, ferry, metro and public transportation come from the timetable; flights are estimate-only (no schedule); rental car, private transfer, taxi and walking are Unavailable with a reason.
- **Selections** of transport use an in-memory list of the most recent search per trip (30 min), so the stored option is always one the server produced.
- **Nominatim** (`OsmMapsProvider`): five new lookups ran 0.9 to 1.4 s apart (1.1 s spacing) and a repeat was served from `geocode_cache` in 2 ms.
- **LiteAPI (verified with a sandbox key)**: `/hotels/rates`, `/hotels/min-rates`, `/data/hotels`, `/data/hotel` and `/data/reviews` all answer on `api.liteapi.travel/v3.0` with the shapes used. A rates call returns up to 200 rate variants per hotel; the rooms list keeps the cheapest per room name, board and cancellation kind (max 12) and gives each a stable id, because provider `rateId`s change on every call. `taxesAndFees` with `included: false` (for example a city tax) is payable at the hotel and is shown separately from the total. Rates, min-rates and prebook are never cached: `http_cache` holds only the list, hotel content and reviews.

## Implementation notes added 2026-10-13 (implementation sync)

- **Hotels list** (`api/src/search/hotels.ts`): only hotels in the traveler's chosen city are kept (the provider matches by city name, so anything listed under another city is dropped); when fewer than 10 remain, hotels within 15 km of the city centre are added. A whole country (no city) lists hotels anywhere in it and gives no distance. Hotels with no room for the stay and party, or whose total exceeds the trip budget (same currency), are hidden and counted (`hiddenCount`); the cheapest total found is returned so the UI can say what would fit. A failed price call lists hotels with prices Unavailable. Room types and maximum per room come from each hotel's own content for the hotels on the page.
- **Rooms**: with no hotel for one room, the UI repeats the search once with about three guests per room and says so (`rooms` query parameter, kept in the URL). The details page and room list carry `rooms`; with several rooms the traveler can pick a type for each room and the cheapest offer holding exactly those rooms is preselected.
- **Flights**: Duffel test offers are fetched when `DUFFEL_ACCESS_TOKEN` is set (searched by place names; the provider finds airports). Offers are Confirmed with real times and marked sandbox; if none come back, the estimate row (price and duration estimated, times Unavailable) is used. A live token is refused at start. Booking itself is documented in plan 007.
- **Transport modes**: the API accepts ten modes (flight, train, bus, ferry, metro, transit, car, transfer, taxi, walking); the UI offers nine chips (no ferry chip). Without a start place the API returns `needsFrom: true` and no rows. Ground estimates are not offered beyond 3,000 km.
- **Places to visit** (`api/src/search/places.ts`): city trips use Overpass (tourism, historic and similar tags, best-known first by Wikidata entry and stated hours, then ordered by the traveler's interests with embeddings for the first 60); whole-country trips use a Wikidata SPARQL list (`WikidataPlaces.ts`) and, if that is busy, say so and suggest picking a city. Only the top 10 are returned (`totalFound` says how many exist). Missing hours, fees and websites are looked up from the map within 150 m by name; anything still missing is shown as "not stated", never guessed. Photos: Commons file from the map data or Wikidata P18; else `GET /api/places/photo` (Wikipedia lead image, then a Commons photo within 150 m whose title names the place), cached 30 days, each with a credit link. Chosen places are stored in `trip_places` from the live list on the server.
- **Banner and background pictures**: `GET /api/places/destination-photo` returns the Wikipedia lead image (photographs only, not flags, maps or logos) for the destination; the page uses lodging terms on Hotels, vehicle terms on Transport and the country on Places (`web/src/lib/destinationPhoto.ts`).
- **Gate**: the trip plan (plan 006) opens once at least one place is chosen; a hotel and transport are optional at that point and the plan says so.
